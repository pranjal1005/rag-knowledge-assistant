Retrieval-Augmented Generation (RAG) Explained
Large language models answer questions using only what was baked into their weights during training, which creates two problems: the knowledge has a cutoff date, and the model has no way to point to a specific source for a claim, so a confident-sounding hallucination is indistinguishable from a fact. Retrieval-Augmented Generation addresses both by giving the model access to an external, searchable knowledge base at answer time, rather than relying solely on what it memorized during training.

A RAG system has two phases. In the indexing phase, documents are split into chunks (small enough to be topically coherent, usually a few hundred words), each chunk is converted into a vector embedding using an embedding model, and the vectors are stored in a vector database alongside the original text and metadata like the source document. In the query phase, the user's question is embedded with the same embedding model, the vector database is searched for the chunks whose embeddings are closest to the question's embedding (nearest-neighbor search, typically using cosine similarity), and those chunks are inserted into the prompt sent to the LLM along with the original question. The LLM is instructed to answer using only the provided chunks, which is what makes the answer groundable and citable.

The main quality levers in a RAG system are chunking strategy (chunks too large dilute relevance, too small lose context), the embedding model (general-purpose vs. domain-tuned), the number of chunks retrieved (too few misses relevant context, too many adds noise and cost), and the generation prompt itself (explicitly instructing the model to cite sources and to say "I don't know" when the retrieved context is insufficient meaningfully reduces hallucination). RAG does not eliminate hallucination entirely -- the model can still misread or over-generalize from the retrieved context -- but it grounds answers in a way that pure parametric generation cannot, and it lets a knowledge base be updated by re-indexing rather than retraining a model.
